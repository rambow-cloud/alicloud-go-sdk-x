### 目标与约束地位

- 验收判断开发者能否在明确业务范围内替代官方阿里云 Go SDK v2，获得一致 Go 接口、正确行为和可控维护成本。
- 本标准与[开发路径](development-path.zh-CN.md)共同约束后续 issue。
- 生成、编译、工具选择、star 或贡献者数量不足以证明产品验收。

- 保留完整固定官方 Darabonba DSL → 官方语义解析器 → 规范化 IR → 本项目 Go 后端 → 公共运行时。
- Smithy 仍是独立本地实验，改变路线需单独 issue/决策。
- 要求 Go 1.27+、直接 JSON v2、核心仅标准库导入、OTel 可选。
- issue、PR 和 Go 注释只使用英文；本项目 Markdown 分为互相链接的中英文文件。

### 必需标准

- 应用指南优先采用可刷新的 STS 角色凭据提供者/cache；长期密钥必须显式注册 StaticProvider/EnvProvider/profile 凭据提供者，LoadDefaultConfig 可发现完整临时环境凭据及原生 Profile，仍支持自定义来源。
- Config/Options 无裸凭据字段，构造期间不进行凭据 HTTP， 请求前拒绝 nil/带类型的 nil；已配置无效来源停止解析。
- #53 离线拒绝/签名/缓存证据仍关联 AC-01/05/11、UX-01/04，#68 优先于其全面禁止发现范围。

| ----- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |

| AC-02 | 准确 action/version/API 字段名、完整支持模型、缺省/零/false/int64/响应容器；JSON v2 严格且容忍未知字段 | 独立 wire 测试数据、签名请求、非法 JSON 和选定 CLI/Explorer 对照；区分全字段/选定字段         |
