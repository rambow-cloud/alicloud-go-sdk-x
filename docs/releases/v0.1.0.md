# v0.1.0 — generated STS

[中文](v0.1.0.zh-CN.md)

- This scoped experimental release targets STS 2015-04-01 through pinned official Darabonba -> official parser -> complete normalized IR -> our Go backend -> shared runtime.
- It is an independent SDK, not an official Alibaba Cloud SDK.
- APIs may change before v1.
- Publication/indexing evidence is recorded separately in the [release checklist](../sts-v010-release-checklist.md); this document alone is not a tag.

### Scope and behavior

- `service/sts` includes all four actions in the pinned source: AssumeRole, GetCallerIdentity, AssumeRoleWithOIDC and AssumeRoleWithSAML; 19 reachable named/ inline models, operation-specific interfaces and deterministic offline Examples.
- The empty GetCallerIdentityInput supplies the uniform context/Input/options call shape without inventing request fields.
- Native field names, absence and response containers are preserved; no artificial STS paginator or waiter is added.

- Service Options, NewFromConfig, operation functional options, small mock seams and shared paginator/waiter conventions follow AWS Go SDK v2 style.
- This is a calling convention, not AWS or official Alibaba source compatibility.
- Native optional fields use pointers and int64 where modeled.
- Outputs add Metadata; inspect service errors with errors.As and cancellation/deadlines with errors.Is.
- Unknown JSON response members are tolerated; duplicate names and invalid UTF-8 are rejected.

- Config/Options accept explicit providers, never bare keys.
- Prefer generated STS -> AssumeRoleProvider -> Cache -> consumer.
- StaticProvider/EnvProvider are deliberate secondary choices; custom providers remain supported.
- Nil/typed-nil providers fail before transport.
- AnonymousProvider explicitly configures OIDC/SAML use; these operations never retrieve source keys or sign.
- Signed actions reject the marker.
- Supply federation tokens/assertions explicitly; federation helpers remain separate.
- User-required #68 adds config.LoadDefaultConfig, native CLI Profile/OAuth discovery, bounded renewal and atomic session persistence.
- Temporary environment sources are discovered; long-lived sources still require explicit provider opt-in.
- Supported CLI modes and precedence are bounded by [the contract](../default-configuration.md).

- Defaults: HTTPS, no authenticated redirects, no retries, 30-second total request deadline, 8-MiB response limit.
- Reviewed opt-in retries remain bounded and idempotency aware; token issuance stays non-retryable.
- Inputs/configuration are copied and clients are concurrency safe.
- Custom providers/transports/hooks must honor their documented contracts.
- Default errors, tracing and sensitive-model String/GoString omit secrets; direct fields and explicit JSON are raw and must not be logged.
- Optional OTel does not configure global exporters/providers.
- Runtime core imports only the standard library; official comparison dependencies live in their own consumer module.

### Evidence and limitations

- All four actions have separate discovered/lowered/emitted/compiled/offline evidence.
- Live scope is cn-hangzhou: #55 accepted actual 900-second AssumeRole expiry renewal and cleanup; #60 generated identity matched six CLI fields/presence using an explicit in-memory OAuth/STS snapshot.
- This is not native SDK Profile/OAuth renewal. #68 separately passed native Profile loading, generated identity reads, forced OAuth exchange, cache reuse and persisted-session reconstruction; see [native evidence](../acceptance/profile-oauth-live.json).
- Actual live refresh-token rotation and waiting for natural OAuth expiry are NOT RUN; offline rotation fixtures remain distinct. **Successful OIDC/SAML live federation: NOT RUN, outside predeclared required live scope.** Their complete offline contracts do not establish working IdP/trust/assertion deployments.
- Explorer browser evidence is separate from CLI/SDK evidence.

- Real source-revision maintenance rehearsal, isolated official STS v2.1.0 comparison and independent docs-only developer evidence are tracked in [the acceptance report](../sts-v010-acceptance-report.md).
- Required independent acceptance and final-commit Linux race/Windows CI precede publication.
- Other available `service/ecs`, `service/vpc`, shared engines and the `services/` bridge retain their separately recorded acceptance; this release does not claim broader ECS/VPC/STS Beta or whole-cloud coverage.
- Benchmarks remain separate.
