# FC 二进制操作生成

[English](fc-binary-generation.md)

- 对应 #92，复用[响应流契约](response-streaming.zh-CN.md)。
- 使用固定的完整 FC DSL、官方语义解析器和现有批量输出器。按二进制操作的程序结构识别，不按操作名写特殊分支。
- 审核请求头模型合并、受条件保护的字符串请求头、准确路径和 query、相同的 body/stream 参数以及响应转换。未知转换或额外语句仍须在写文件前拒绝。
- 保留原始请求字节。操作输入将 DSL 的 `readable` 映射为独立复制、最多 8 MiB 的 `[]byte`，以支持签名和重放，不接管调用者的 reader。这是明确的 v0 API 取舍，不宣称与官方源码兼容或支持无限制上传。
- 保留原生请求头模型和线路字段名。复制通用请求头后，专用字段覆盖同名键，与 DSL 一致；受 SDK 管理或格式错误的请求头仍在获取凭据前报错。
- 输出 `Body` 为调用者持有的 `io.ReadCloser`，同时提供原生响应头、状态码和 Metadata。调用者负责关闭；大小限制、超时和错误遵循共享运行时。默认保守策略不重试函数调用，也不因后续读取失败重试。
- 固定的 OpenApi 0.3.23 第 901–905 行优先处理 request.stream，对其字节签名并设置 application/octet-stream；二进制响应直接返回正文，不做 JSON 解码。
- 验证准确字节、签名摘要、路径、请求头缺失语义、输入归属、懒读取、取消、大小限制及结构化错误；通过重命名产品和操作证明可复用。同步生成确定性 Example 和无效输入写前拒绝测试。
- 使用 Node 22 完成前端测试和检查，再生成并执行 Go 文档检查、vet、测试和格式检查。为二进制类型明确升级 IR schema/profile，重新生成归属产物，保留来源和许可原始字节。
- 现有只读资源授权不包含真实函数调用；生成、编译和离线验收分别记录。

- 已完成离线实现：schema v6 / openapi-http-v1；发现、降低、生成并编译 73 个 FC 操作，输出 335 个模型及 73 个可执行操作 Example。
- 来源和许可原始字节，以及 STS/ECS/VPC 的可执行 Go 产物保持不变。其 IR 和说明哈希随 schema 升级重新生成。
- Node 22：前端一致性检查及全部 105 项测试通过；新增的二进制源码变化写前拒绝测试单独通过，共覆盖 106 项。
- 17 个公共包的文档检查、vet、生成一致性、格式和语言及本地链接检查通过。首轮全量测试中除 codegen 外的包全部通过；修正其重命名夹具的来源坐标后，相关 codegen 测试通过，包含完整隔离编译及无效二进制 IR 测试，耗时 31.550 秒。
- 复用夹具使用官方解析器重新解析改名后的产品、操作、请求头模型及请求和响应字段，再编译运行生成的客户端。无效映射、转换、签名算法及选中源码变化在写文件前失败。
- 1605 个字段中，1123 个有上游英文业务说明，全部 1605 个有 Go 契约注释。缺失业务说明仍归 #93。

- 记录了原生源码哈希和准确提交，没有复制原生 Go 实现或新增运行时依赖。这些事实不代表所有版本或真实云行为均已一致。
