## 测量范围

- 调用生成的 STS `GetCallerIdentity`，使用虚构临时凭据和相同的注入响应传输器。
- 耗时包含签名、编码、传输调用和响应解码；客户端构造不计入运行时循环。
- 顺序执行三次各一秒的运行时采样。报告保留各次样本及完整依赖列表。
- 冷缓存、热缓存编译各测一次。两套独立空缓存包含标准库编译成本，不计模块下载。
- 两个程序均使用 `go build -trimpath`，不剥离链接信息；先测本 SDK，再测官方 SDK。
- 不访问网络或云账号，不涉及真实凭据及资源信息，不删除全局缓存。

## 结果限制

- 结果仅适用于这一台 Windows 机器上的 STS 测试，不能预测其他服务、真实网络延迟或生产吞吐量。
- 编译耗时受机器负载、存储和杀毒软件影响；不据此宣称统计显著性或普遍性能优势。
- 官方方法的 context 接口不同。取消、重试、服务覆盖和凭据续期由其他验收测试负责。
- CI 在 Linux 和 Windows 验证测试行为并运行 vet，不为这些机器相关的耗时和大小设置门槛。
- 官方依赖放在独立 Go 模块中，SDK 核心继续只依赖标准库。
