# SDK 缺口补齐路线

[English](gap-completion.md)

- 决策日期：2026-10-09。
- 用户要求补齐目前发现的 SDK 缺口。
- 本路线沿用已验收的 Darabonba 生成流程，并替代过时的下一步安排。
- 当前基线：STS 4、ECS 380、VPC 403 个操作已生成。生成、编译、策略审核、离线行为、真实云行为与发布分别统计。
- 每项可独立评审的修改使用单独 issue 和分支。不能把未知行为标成已审核来凑齐覆盖率。

## 开发顺序

1. 修正当前路线、覆盖数字和验收文档；保留历史证据及其版本。
2. 扩展原生分页器、生命周期 waiter、输入校验和保守重试策略。按完整 IR 解析路径，记录每项操作的依据；不能仅凭名称推断分页或重试安全性。
3. 增加可续期的 OIDC/SAML STS provider 和 token 文件读取，复用生成的 STS 客户端及公共凭据缓存。每次刷新重新读取 token。
4. 扩展凭据来源：ECS 实例元数据、URI、外部进程和 CloudSSO。实现前明确有界读取、刷新、优先级、脱敏与配置规则。长期密钥仍须显式启用。
5. 根据固定的官方声明及经审核的地域、网络规则扩展 endpoint；保留显式覆盖与不支持组合的错误。
6. 扩展协议降低与运行时，支持 ROA、JSON 请求体、XML 和流式场景。使用固定官方产品进行验收；仅有公共辅助函数不算产品验收。明确流的所有权、重定向与重试可重放性。
7. 改善文档覆盖，按经审核的来源补充缺失说明，并保持中英文指南语义对应；不能声称输入中不存在的译文已经提供。
8. 在 #20 下完成可复现的运行时与依赖对比，记录版本和实际结果，包括不利结果。
9. 在 #79 下完成已授权的真实云行为验证，并验证 OAuth token 轮换。真实联邦登录、人工体验（#76）、发布（#61）和索引分别记录。

## 验收要求

- 每项实现同步提供行为测试、输出确定的离线 Example、包文档和配对指南。
- 生成器修改执行官方前端测试及检查、确定性生成检查，并验证无效输入不会写入产物。
- 相关 Go 修改执行格式、文档、vet 和测试检查；CI 验证 Linux race 与 Windows。
- 能力清单区分适用、已审核、未审核及不支持范围。操作覆盖不代表适配器覆盖。
- 真实云验证先记录账号及资源范围，优先使用已有的已授权资源。创建资源前须明确具体范围；不能为了获得通过结果而自行创建收费资源。
- 代理执行结果不能记作独立人工体验。
- 发布和浏览器索引检查实际完成后才能关闭对应验收项。

## 跟踪方式

- 新建实现 issue 统一关联缺口补齐父 issue。
- 复用 #20、#76、#79 和 #61，保留原有证据及范围；调整范围时明确记录。
- 必需子项与证据全部完成后，才关闭父 issue。
