# 文档写作规范

[English](documentation-style.md)

- 英文使用 `name.md`，中文使用同目录下的 `name.zh-CN.md`。
- 每份指南都提供语言切换链接；修改内容时同时更新两份文件。
- 使用短句和要点列表。代码示例和对照表按需保留。
- 中文按自然的阅读习惯表达，不逐词硬译。技术术语首次出现时解释，API 名称保持原样。
- 两份指南各自包含用法、默认值、限制和证据；读者不应为查找命令或来源而切换语言。
- GitHub issue、issue 草稿、表单和 PR 模板只使用英文。
- Go 注释、诊断信息和标识符使用英文。
- 先修改生成模板，再重新生成指南；不直接修改生成文件。
- 上游原始文档和许可证通知保持原始内容，不参与改写。
- CI 检查文件配对、语言切换链接、本地链接及 issue 文件的英文要求；翻译准确性由人工评审。

本规范根据用户于 2026-10-09 提出的要求制定，取代此前在同一 Markdown 文件中混排中英文的规则。SDK 行为和发布验收标准不变。

## 本次整理范围

- 69 份项目指南分别提供英文和中文文件。
- 49 个历史 GitHub issue 已改为纯英文，状态、标签和里程碑保持原样。
- 两套生成器都输出分开的语言文件。
- 运行时代码、固定的 DSL/元数据、来源许可证和七份上游 README 保持不变。
- 原生 Profile/OAuth 与 STS 的验收证据继续保留；独立开发者验收、发布和索引仍待完成。
