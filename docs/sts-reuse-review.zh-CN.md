# STS 可复用性评审

[English](sts-reuse-review.md)

- 跟踪 issue：[#72](https://github.com/rambow-cloud/alicloud-go-sdk-x/issues/72)。
- 评审已验收的 STS 基线，保留公开构造器和固定的上游源文件。
- 按照[开发路径](development-path.zh-CN.md)，先记录发现、建立 issue，再实现和验证。

## 各层如何复用

- 官方 Darabonba DSL 和官方语义解析器提供操作、模型及协议行为。
- 完整 IR 驱动 `service/sts` 生成。四个操作使用同一套产品生成器，没有手写操作绕过流程。
- 本次范围内的操作：`AssumeRole`、`GetCallerIdentity`、`AssumeRoleWithOIDC`、`AssumeRoleWithSAML`。
- 公共运行时提供签名、端点解析、中间件、错误和重试策略；凭据签发操作仍不重试。
- `feature/stscreds` 是基于生成的 `AssumeRoleAPI` 编写的凭据适配器，不另外实现 STS 请求协议。
- `credentials.Cache` 统一处理刷新合并和过期；原生 Profile 的角色配置也使用生成客户端及同一套适配器和缓存。
- 已审核的角色校验规则放在共享内部组件中，不通过旧版请求模型转换原生输入。
- `services/sts` 保留为有限范围的兼容实现，旧构造器继续可用；新的生成路径不经由它执行请求。

## 发现与修复方案

- **选项所有权：**兼容 provider 把内部选项切片直接交给自定义 API。改为每次调用都复制，并测试 API 修改输入和选项后的行为。
- **校验耦合：**生成客户端的 provider 为校验而构造旧请求类型。提取共享内部校验器，保留已接受规则，不改变字段是否存在的语义及整数宽度。
- **文档模板复用：**匿名操作说明写死了 STS 操作名。改为从 IR 提取；STS 联邦身份验收范围只出现在 STS 指南中。
- 两个构造器共用取消处理和返回凭据校验；各自保留对应 API 类型的请求、响应适配。

## 验证计划

- 修复前复现选项被修改的问题，修复后验证连续及并发读取。
- 使用官方语义解析器解析改名后的签名、无请求参数及匿名操作。这是合成的复用测试，不代表新增服务覆盖。
- 用共享后端生成并编译一个不同名称的合成产品，检查指南操作名和认证模式。
- 先执行 Node 前端检查和测试，再执行 Go 再生成检查、文档检查、vet、包测试、消费者测试和格式检查。
- 在下方记录本地结果；最终 PR 提交还须通过 Linux race 和 Windows CI。

## 范围边界

- STS 没有分页器或 waiter，不根据名称或字段猜测这些能力。
- OIDC/SAML 原始操作已生成；自动续期的联邦身份 provider 和真实联邦验收需要另行定义范围。
- 保留旧构造器意味着 `feature/stscreds` 仍因其公开签名导入兼容包。本次移除的是主路径对旧类型的校验依赖，不改变兼容签名。
- 保留已有[真实续期证据](live-sts-renewal.zh-CN.md)，本次评审无需再次调用云 API。
- 独立人工验收（#60）和发布、索引（#61）仍单独跟踪。

## 结果

- 三项问题均已修复，没有改变公开签名、来源版本、生产 IR、策略及生成的 STS Go 代码。
- 修复前选项修改回归测试失败；修复后连续调用和八次并发调用均通过。已有原生 provider、缓存和 Profile 测试也通过。
- Node 22 前端检查和全部 57 项测试通过。合成夹具修正自身逻辑来源路径后重跑通过；生产来源校验没有放宽。
- 本地再生成检查、文档检查、vet、Go 包测试及 Example、独立消费者测试、格式检查均通过。
- 独立模块仅使用公共运行时，就能编译并运行 ECS、STS、VPC 和改名后的合成产品。合成产品的四次调用保留原生字段和认证行为，只有两个签名操作读取来源凭据。
- CI 仍是合并门禁，最终 Linux race 和 Windows 结果记录在 #72 及其 PR；本地通过不替代 CI。
