# OSS 语义 IR

[English](oss-semantic-ir.md)

- 对应 #92，承接已经合并的 [OSS 运行时](oss-runtime.zh-CN.md)。
- 使用现有固定版本，纳入完整官方 OSS DSL 及导入模块，保持源码和许可证通知的原始字节。
- 使用官方语义解析器，自动发现全部操作和可达模型，不维护手工操作白名单。
- 严格识别 Gateway 初始化、桶地址映射、查询参数的条件赋值、协议常量和 execute 调用。
- 将 XML 响应的根节点和嵌套字段名称、类型、单值或数组形态，与固定哈希的原生 Go AST 事实比较。差异同时保留两边源码位置，不自动修改。
- 为不带请求正文的 XML 读取操作生成可复用 IR，并保留经过核对的根节点语义。其他操作仍列入清单，给出确定的不支持原因。
- 本阶段验收生成器前端。Go 后端能够消费这些语义后，才把暂存的 OSS 源码加入生产产品列表；现有四个产品的产物仍由原生成流程维护。
- 下一阶段实现通用 Go XML 输出，通过改名产品的编译和运行时测试，交付 service/oss、包文档和离线 Example。随后补充经过审核的请求正文、分页和完整性策略。本阶段不宣称真实云验收。

## 验收要求

- 完整官方 OSS 操作发现和语义投影无需联网，结果可重复。
- 改名的合成产品复用同一个降低器，不依赖 OSS 操作名称，也能生成相同的协议语义。
- 修改 Gateway 初始化、地址映射、查询、正文或运行时交接的测试必须拒绝不支持的流程；递归检查能发现嵌套 XML 差异。
- 缺失根节点、包装层差异、未支持正文和不安全模型均给出明确原因。显式选择不支持的操作时，写文件前失败。
- 先运行 Node 22 前端检查和测试，再运行 Go 生成检查、文档检查、vet、测试及格式检查；CI 验证 PR 最终提交。
- 中英文文档区分操作发现、语义降低、Go 输出、编译和真实云验收。

## 已知来源差异

- ListBuckets 的 DSL 正文字段以小写开头，桶列表为直接数组；原生 XML 使用首字母大写的字段和 Buckets/Bucket 包装层。
- CORSRule.AllowedHeader 在当前 DSL 中是单值，在固定版本的原生模型中是数组。
- 新 DSL 中有而旧原生辅助模块没有的字段仍保留在发现结果中，不能为了匹配而删除。
- 源码比较只属于静态证据。批准修正前，需要单独记录 Explorer 浏览器核验或真实云行为证据。
