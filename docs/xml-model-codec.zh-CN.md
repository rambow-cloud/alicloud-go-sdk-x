# 公共 XML 模型编解码层

[English](xml-model-codec.md)

- 对应 #92，接续 PR #115/#116 的内部运行时阶段。
- 复用[固定版本的 OSS 对比](../tools/ossxml/README.zh-CN.md)和[完整来源发现](oss-xml-protocol.zh-CN.md)。字段以完整 DSL 为准，原生 helper 声明补充 XML 根元素证据。
- 使用标准库实现内部编解码器。显式指定准确的根元素名及标量根对应的字段，不从操作名推断。字段使用原生 JSON 线名称标签，保持 DSL 生成模型的结构。
- ACL/CORS 的结构根不额外保留包装层；LocationConstraint 标量根保留对应字段。使用改名的合成模型，验证能力可以跨产品复用。
- 保留可选指针、显式空值和重复元素。响应中的未知子元素允许忽略，以兼容新增字段；拒绝重复的单值字段、畸形文档、错误根元素、不支持的类型和歧义绑定。
- 仅接受一个 UTF-8 文档，限制字节、深度和元素数量，并检查 context。拒绝指令、不支持的处理指令和模型中的混合内容。错误文本不包含原文，解码失败不发布部分结果。
- 根据审核过的根元素和具体模型，生成确定且正确转义的 XML。不支持的类型、循环模型或超限输出在返回字节前报错。测试不使用账号、网络或凭据，不调用云 API 或创建资源。
- 验收包括独立的合成请求/响应用例、确定输出的外部 Example、根模块 Go 文档检查/vet/测试、格式、配对文档以及最终提交的 Linux race/Windows CI。
- 本阶段不增加公共操作、OSS 签名或 XML 生成器。生产 OSS 接入仍须把固定来源/helper 的线协议特征纳入 IR，处理端点和子资源、OSS 签名以及流与校验和契约；不能宣称已生成 OSS 或完成整个 #92。
