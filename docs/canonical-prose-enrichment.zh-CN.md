## 路线

- 根据现有完整 IR 自动获取 STS、ECS、VPC 对应元数据，原始源码、许可字节及哈希保存在 `sources/openapi-meta/prose/`，不修改已有规范化夹具。
- 先完成表示层规范化：准确线字段名、索引输入及 itemName 响应包装。对不支持的元数据或缺失映射提供确定性的原因。
- 将候选说明对应到完整 DSL 模型字段及原生线类型。只补充没有上游英文说明的字段，不覆盖已有说明、不改变模型。
- 输出确定性、绑定来源的说明投影和覆盖，保留文件哈希、JSON 指针；不增加逐 API 编写配置或手选字段的前置要求。
- 投影是可选文档补充，缺失不阻止完整服务生成。来源漂移、字段引用无效或源码被修改须在写入前失败。
- 生成英文注释、配对的用法及来源覆盖，注明 Apache 归属；不把上游账号和资源示例变成可执行测试。

## 验收

- 规范化及映射夹具覆盖数组、包装、索引输入、歧义冲突和不支持的结构。
- 检查来源原文、哈希、缺失语言及覆盖原因。冲突映射须拒绝或明确排除，不能猜测说明。
- 证明可执行操作、模型定义及能力策略不变；允许注释和文档变化。
- 可选来源缺失、源码漂移或投影无效时不产生部分写入。
- 执行 Node 22 投影检查与测试、sdkgen check/product-check、doccheck、vet、格式、Go 测试和最终提交 CI。
- 生成后报告实际新增说明数量及剩余缺口，不预先承诺全部字段业务说明已经补齐。
