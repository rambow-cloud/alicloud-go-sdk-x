## 强制刷新范围

- 使用真实时钟，不模拟时间流逝，不宣称凭据已经自然到期。
- 在 SDK 会话锁下，仅使选定 Profile 中缓存的 STS、access token 到期时间失效；token 值和其他配置保持原样。
- 使用原生 SDK 加载器和 provider，执行真实 OAuth refresh grant、真实 STS 交换，以及生成的 GetCallerIdentity 读取。
- 检查服务端是否实际替换 refresh token；没有替换就不能证明轮换。
- 验证缓存复用、原子持久化、非认证配置不变、重建 provider 后复用会话，以及会话锁释放。
- 刷新请求若在任何 token 更新前失败，在锁下恢复原到期时间。服务端轮换成功后，绝不恢复旧 token。
- 不记录原始传输数据，报告只包含次数、布尔值、源码提交和脱敏状态。

## 自然到期续期计划

- 使用上次成功刷新签发的会话：STS 凭据原始到期时间为 UTC 2026-10-09 19:19:56，access token 为 19:19:57。
- 等待真实时间超过两个到期时间；不修改缓存时间、token 或 provider 的时钟。
- 执行前核对原始到期值和配置文件修改时间。如果其他进程提前更换会话，如实记录未验收这次会话。
- 新建原生 provider，执行一次真实刷新和 STS 交换，再调用两次生成的身份查询。检查缓存、持久化后重建复用、token 更换、其他配置保持不变及锁释放。
- 记录实际 SDK 提交和起止时间。OIDC/SAML 真实联邦验收仍单独跟踪；不公开凭据或身份值。

## 仍需单独完成的用例

- 只有观察到真实墙上时间到期，才能记录自然 OAuth 到期通过；否则保持未执行。
- OIDC/SAML 真实联邦验证等待用户提供角色和 IdP 配置。
- 强制刷新不能代替 #94 的完整验收。
