# ROA 响应模式

[English](roa-response-modes.md)

- 对应 #92 的公共运行时阶段；本次不增加 FC 生成覆盖，也不宣称支持 XML 或流式响应。
- 依据：固定 OpenApi 0.3.23 的 `main.tea` 第 964–1036 行。官方错误解析兼容 `Code`/`code`、`Message`/`message` 和 `RequestId`/`requestId`；FC 2023-03-30 的 DSL 包含 JSON 与 `none` 响应声明。
- 零值继续使用 JSON。没有类型化成功正文的操作需要明确选择已审核的 `none` 模式，不根据 HTTP 状态或方法推断。
- 成功的 `none` 响应仍受读取大小限制，读取后丢弃正文，返回新的零值输出和响应头中的请求 ID。不要求 JSON，也不调用模型解码器。
- 错误响应仍解析为结构化 JSON 服务错误。大写成员明确存在时优先使用，否则读取对应小写成员。保持严格 JSON 解析，不开启全局忽略大小写。
- 读取错误、大小限制、取消、响应关闭、中间件及保守重试规则继续生效。未知模式在获取凭据和发送 HTTP 请求前失败。

## 验证计划

- 独立测试覆盖空的 204、非 JSON 的 200、无效或超大正文、读取失败、错误成员优先级、重复 JSON 成员和未知模式。
- 检查输出重新赋值、响应头元数据、正文关闭、不调用自定义解码器和 context 取消。
- 提供无需账号的可执行 Example，以及英文包和符号注释。
- 执行格式、文档、vet 和 Go 测试；合并前要求当前提交的 Linux race 与 Windows CI 通过。
- 完整官方产品降低、类型化正文/请求头/路径生成、XML 和流所有权仍在 #92 中跟踪。
